# VERIFICATION — 속닥속닥 전수 점검 절차

이 문서는 속닥속닥을 기능·보안·데이터·배포 전 영역에 걸쳐 점검하기 위한 체크리스트다.
한 번에 다 하지 않아도 된다. 영역별로 독립적이며, 순서는 위에서부터 권장 순서다.

각 항목 형식: `확인 대상 → 실행 방법 → 기대 결과`.

발견한 문제는 [버그 기록 양식](#버그-기록-양식)에 맞춰 남긴다.

---

## 0. 자동화 검증 (가장 먼저, 코드 변경이 있을 때마다)

| 명령 | 기대 결과 |
|---|---|
| `npm run lint` | `0 errors` (warning은 허용하되 신규 warning이면 기록) |
| `npm run typecheck` | 종료 코드 0, 출력 없음 |
| `npm test` | unit 전부 pass + workers/integration 전부 pass |
| `npm run test:e2e` (또는 `test:e2e:chromium`) | 실배포 DO 필요 테스트 1건만 skip, 나머지 pass |
| `npm run build:worker` | 성공. 기존 경고(Windows OpenNext, ChatRoom export, duplicate "options")는 알려진 오탐 |
| `npm run db:audit:local` | 위반 0건 |

실패하면 그 단계에서 멈추고 원인부터 잡는다. 위를 통과 못 한 상태의 수동 점검은 의미가 없다.

## 1. 배포·인프라

- [ ] `https://sokdak.sokdak.workers.dev/` → 200, `속닥속닥` 렌더
- [ ] `/login` → 200, 설정된 OAuth 제공자 버튼만 노출
- [ ] `wrangler deployments list`로 현재 버전 ID가 최신 커밋과 일치하는지 확인
- [ ] 바인딩 확인(배포 로그 또는 대시보드): `DB`, `MEDIA_BUCKET`, `CHAT_ROOM`, rate limit 3종, `ASSETS`
- [ ] 시크릿 존재 확인: `BETTER_AUTH_SECRET`, `TURNSTILE_SECRET_KEY`, (`NAVER_CLIENT_SECRET` — Naver 활성화 시)
- [ ] `sokdak.kr` 도메인 연결 상태 — 미연결이면 `BETTER_AUTH_URL`과 불일치로 소셜 로그인 불가(알려진 제약)
- [ ] Turnstile이 실제 위젯 키인지 확인 — 테스트 키(`1x000…AA`)면 봇 방어 없음(알려진 제약)

## 2. 게시판 목록 (`/`)

- [ ] 테이블 헤더: 번호 / 제목 / 글쓴이 / 날짜 / 조회 / 추천
- [ ] 공지(`is_notice=1`)가 최상단에 고정되고 공지 배지 표시
- [ ] `?sort=popular&window=day`에서도 오래된 공지가 사라지지 않는다
- [ ] 일반 글 번호가 `total - (page-1)*perPage - index` 규칙으로 내림차순
- [ ] 오늘 글은 시각(HH:MM), 이전 글은 월/일 표시
- [ ] `?page=2` 이동 → 다른 글 집합, 번호 연속. 범위 밖 페이지 → 마지막 페이지로 클램프
- [ ] 댓글 수 뱃지, 미디어 첨부 표시
- [ ] 모바일 뷰포트(≤640px): 제목 행 아래 작성자·날짜·조회 메타 라인
- [ ] 정렬 전환(최신/인기) 시 쿼리 파라미터와 결과가 일치
- [ ] 빈 결과(없는 페이지 조합) → 빈 상태 문구, 레이아웃 깨짐 없음

## 3. 글 상세 (`/post/[id]`)

- [ ] `← 목록` 링크 동작, `No.N`, 조회수 표시
- [ ] 새로고침/재방문 시 조회수 증가
- [ ] 작성자 표시가 `익명(xxxx)` — username·프로필 링크·이미지 없음
- [ ] 제목/본문 XSS: `<script>`, `<img onerror>` 입력 시 문자열로 렌더
- [ ] 삭제/숨김 처리된 글 → 접근 시 적절한 응답(404 또는 숨김)
- [ ] 비로그인 접근 가능 여부(제품 정책 확인)와 글쓰기 버튼의 로그인 유도

## 4. 댓글

- [ ] 댓글 번호가 글별로 1부터 순차 부여(`No.N`)
- [ ] 동일 작성자가 같은 스레드에서 같은 익명 태그, 다른 스레드에서 다른 태그
- [ ] OP 댓글에 `글쓴이` 배지
- [ ] `>>N` 인용 버튼 → 본문에 `>>N` 삽입, 렌더 시 `#comment-N` 링크로 변환
- [ ] 인용 클릭 시 해당 댓글 앵커로 스크롤
- [ ] 답글 depth 제한(초과 입력 거부)
- [ ] 댓글 작성/수정/삭제 권한 — 본인 것만 가능, 타인 것은 버튼 미노출 + API도 403
- [ ] 차단된 작성자의 댓글 → 톰브스톤(내용 숨김) 표시
- [ ] 레거시 `num=0` 댓글: 중복 `id="comment-0"` 없음, `>>0` 버튼 없음
- [ ] 더블 클릭/연타로 댓글 중복 생성 안 됨(`request_id` 멱등)

## 5. 익명성 경계 (최우선 보안 항목)

브라우저 개발자도구 → Network에서 `/i/api` 응답 또는 페이지 소스를 확인:

- [ ] 게시판 목록/상세/검색 응답에 `username`, `author_id`, `displayName`, `image` 필드가 없다
- [ ] 알림 목록에서 게시판 알림의 액터가 `익명`으로 표시
- [ ] `/u/[username]` — 비로그인 또는 타인 접근 시 404
- [ ] `/api/profile/[username]` — 비본인·비관리자 접근 시 403/404
- [ ] `/api/users/[username]` 동일하게 제한
- [ ] 검색 결과에 계정 섹션 없음(게시물만)
- [ ] 설정의 차단/뮤트 목록이 404로 가는 `/u/` 링크를 포함하지 않음
- [ ] 예외: DM 요청/수락 알림만 실제 `@username` 액터 노출(의도된 동작)

## 6. 개인 제어 (숨기기/뮤트/차단/저장/신고)

- [ ] 글 옵션 → 숨기기: 목록에서 즉시 제거, 새로고침 후에도 유지
- [ ] 글 옵션 → 뮤트: 작성자 글이 목록에서 사라짐, **현재 보고 있는 글 카드가 unmount되지 않고** 확인 메시지 표시
- [ ] 글/댓글 → 차단: 해당 작성자 콘텐츠 숨김 + 상호작용 차단
- [ ] 차단 후 좋아요 시도 → 서버가 거부(alert/에러 메시지), 낙관적 UI가 롤백
- [ ] 설정 → 개인정보에서 차단/뮤트 해제 가능
- [ ] 저장 → `/saved`에 표시, 해제 시 제거
- [ ] 신고 → 사유 제출 후 관리자 신고 큐(`/admin/reports`)에 나타남

## 7. 인증

- [ ] Kakao 로그인 플로우 완주(도메인·콜백 설정 후)
- [ ] Naver: `NAVER_CLIENT_ID` 설정 시 버튼 노출, 미설정 시 숨김
- [ ] 신규 계정 → 온보딩(프로필/username 설정)으로 이동
- [ ] 세션 만료/로그아웃 정상
- [ ] 설정 → 연결된 계정: Kakao/Naver 연결·해제, 마지막 1개는 해제 불가
- [ ] 같은 이메일의 다른 제공자 계정이 자동 연결되지 않음(명시적 연결만)

## 8. 알림

- [ ] 댓글/답글 알림 생성, href가 `/post/{id}#comment-{num}` 딥링크
- [ ] 알림 클릭 시 해당 댓글 앵커로 이동
- [ ] 읽음 처리, 읽지 않은 수 뱃지
- [ ] DM 요청/수락 알림만 실제 액터 표시

## 9. DM (`site_settings.dm_enabled`)

- [ ] 플래그 off → DM UI/라우트 비활성
- [ ] on → 요청 전송/수락/거절, 메시지 송수신, 실시간(ChatRoom DO) 수신
- [ ] 차단한 상대에게 요청 불가
- [ ] 메시지 이력이 D1에서 복구 가능

## 10. 관리자/모더레이션

- [ ] 관리자만 `/admin/*` 접근, 일반 유저는 리다이렉트/403
- [ ] 글 옵션에 공지 등록/해제 표시(관리자만)
- [ ] 신고 큐: 신고 목록, 대상 글/댓글 링크, 처리 액션
- [ ] 사용자 관리: 경고/밴/섀도밴 — 밴된 유저 로그인 차단, 섀도밴 유저 콘텐츠 자신에게만 보임
- [ ] `site_settings` 변경이 즉시 반영

## 11. 검색

- [ ] 게시물만 검색, 계정 검색 없음
- [ ] 작성자 표시가 익명 태그
- [ ] 차단/뮤트/숨김 작성자의 글은 결과에서 제외
- [ ] 빈 검색어/결과 없음 상태

## 12. i18n

- [ ] 언어 전환(ko/en)이 모든 신규 UI에 적용 — 빠진 키는 영어 폴백이 아닌 키 문자열이 보이면 버그
- [ ] `board.*`, `comments.*`, `settings.linkNaver` 등 신규 키 양쪽 언어 존재
- [ ] 날짜/시간 포맷이 로케일에 맞음

## 13. 보안·경계

- [ ] `/api/*` 직접 접근은 bearer-key 경계 — 키 없으면 401
- [ ] `/i/api`는 브라우저 전용 터널 — 앱 외 Origin 차단
- [ ] rate limit: 짧은 시간 내 반복 요청 시 429 (write 경로, 로그인, 검색)
- [ ] Turnstile 미통과 시 글쓰기/로그인 차단
- [ ] `user.id` 불변 — username 변경 후에도 소유권·관계 유지
- [ ] CSRF: 다른 Origin의 폼/fetch가 상태 변경을 못 함

## 14. 데이터 무결성 (D1)

```bash
npx wrangler d1 execute sokdak-db --remote --command "PRAGMA foreign_key_check"
```

- [ ] 위반 0건
- [ ] `comments.parent_id`가 `comments.id`를 참조(자기참조 정상)
- [ ] `posts.comment_count`와 실제 댓글 수 일치:

```sql
SELECT p.id, p.comment_count, COUNT(c.id) AS actual
FROM posts p LEFT JOIN comments c ON c.post_id = p.id
GROUP BY p.id HAVING p.comment_count <> actual;
```

- [ ] 댓글 `num`이 글별 유니크: `SELECT post_id, num, COUNT(*) c FROM comments GROUP BY post_id, num HAVING c > 1;` → 0행
- [ ] 익명 태그 결정성: 같은 `(post_id, author_id)`면 항상 같은 태그

## 15. 성능·엣지

- [ ] 첫 페이지 로드 < 3s (일반 네트워크)
- [ ] 글 많은 상태(수백 개)에서 페이지네이션 정상
- [ ] 제목 매우 긴 글, 본문 없는 글, 이모지/특수문자 포함 콘텐츠에서 레이아웃 안 깨짐
- [ ] 오프라인/느린 네트워크에서 폼 제출 실패 시 에러 메시지, 데이터 유실 없음

## 16. 접근성·모바일

- [ ] 터치 타깃 ≥ 44px
- [ ] 키보드만으로 글쓰기·댓글·메뉴 조작 가능
- [ ] 스크린리더: 익명 태그, 공지 배지, 조회수에 적절한 레이블
- [ ] iOS Safari, Android Chrome에서 레이아웃 확인

## 버그 기록 양식

문제 발견 시 아래 형식으로 기록한다:

```text
### [심각도] 요약
- 심각도: critical(데이터 유실/신원 노출/보안) | major(기능 불능) | minor(UX/표시)
- 위치: URL / 컴포넌트 / API 경로
- 재현: 1) ... 2) ...
- 기대: ...
- 실제: ...
- 환경: 로컬/라이브, 브라우저, 로그인 여부
- 증거: 스크린샷, 콘솔/네트워크 로그, 쿼리 결과
```

## 점검 후 정리

- 발견된 버그는 심각도 순으로 수정하고, 각 수정에 회귀 테스트를 추가한다.
- 점검이 끝나면 이 문서의 체크박스를 채우거나, 발견 목록과 수정 내역을 커밋 메시지에 요약한다.
- 알려진 제약(미연결 도메인, Turnstile 테스트 키, 빈 라이브 DB 등)은 버그가 아니라 별도 목록으로 관리한다.
